# Morrow Calendar

Morrow is now a deployable Flask web application for birthdays and events.
The original Tkinter desktop version is retained as
`birthday_event_calendar.py`; Render runs the browser version from `app.py`.
The web version includes a private sign-in screen and PostgreSQL support.

## Run locally

Use Python 3.10 or newer:

```bash
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows:
# .venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Open <http://localhost:5000>.

The web app includes:

- responsive monthly calendar view;
- add, edit, and delete birthdays and events;
- yearly recurring birthdays;
- event times, notes, colors, and all-day dates;
- upcoming dates panel;
- JSON import and export;
- SQLite storage;
- private username/password sign-in;
- CSRF protection for calendar changes;
- PostgreSQL support through `DATABASE_URL`;
- AI date suggestions using OpenAI or Groq;
- optional Tavily web research to ground those suggestions;
- `/healthz` health check;
- API configuration status that never reveals secret values.

## Deploy to Render

The repository includes `render.yaml`, so the quickest route is:

1. Revoke the API keys that were pasted into chat and create fresh keys.
2. Push the repository to GitHub. Never commit `.env` or real key values.
3. In Render, choose **New → Blueprint**, connect the GitHub repository, and
   select `render.yaml`.
4. When Render prompts for secret values, provide:
   - a username for `ADMIN_USERNAME`;
   - a strong password for `ADMIN_PASSWORD`;
   - the fresh values for the API keys. If Render does not prompt, open the
     service's **Environment** settings and add:

   ```text
   ADMIN_USERNAME
   ADMIN_PASSWORD
   OPENAI_API_KEY
   TAVILY_API_KEY
   GROQ_API_KEY
   ```

5. Deploy. Render uses:

   ```text
   Build: pip install -r requirements.txt
   Start: gunicorn --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120 app:app
   ```

6. Verify the deployment at `/healthz`. A healthy response is:

   ```json
   {"auth_configured":true,"service":"morrow-calendar","status":"ok"}
   ```

7. Open the Render URL, sign in with the `ADMIN_USERNAME` and
   `ADMIN_PASSWORD` values, and create a test event.

The Blueprint also creates a Render PostgreSQL database and connects it to the
service through `DATABASE_URL`. The calendar itself works without AI. When you
click **AI ideas**, the server uses Tavily for optional web research and then
sends the request plus short research snippets to either OpenAI or Groq. The
API keys stay on the server and are never sent to the browser. Their labels
(`ca3`, `flexi`, and `ca`) are not used in code.

## Data persistence

The Blueprint's free PostgreSQL database is suitable for testing but Render
documents limitations and expiration for free databases. For long-term
production use, upgrade the database to a paid plan or provide a managed
PostgreSQL `DATABASE_URL`. The application keeps SQLite as a local-development
fallback when `DATABASE_URL` is absent.

This version is intentionally a single-calendar app with one admin account.
For multiple independent users, add a user-registration flow and associate
events with user IDs before opening it to a broader audience.

## Security

- Keep real credentials in Render Environment settings or a local untracked
  `.env` file.
- Never put passwords or API secrets in GitHub, `render.yaml`, JavaScript, or
  HTML. `SECRET_KEY` is generated by the Blueprint.
- The app's `/api/integrations` endpoint returns only `true`/`false`
  configuration status.
